# 按任务选择指标：推荐组合与最小评测包

## 2. 三档可执行方案

### A. 快速回归测试（每次模型/参数更新）

- 固定 100–300 条覆盖失败模式的内部 prompt，另加公开 GenEval 2 子集。
- 每 prompt 至少 2 个固定 seed；固定输出分辨率与 sampler。
- 自动分：Soft-TIFA 或 VQAScore + 一个偏好分 + 内部规则/检测器。
- 编辑任务：指令成功 + 掩码外 LPIPS 两个轴。
- 输出逐样本 JSONL，保存图像、prompt、seed、完整配置和失败原因。
- 目标：发现回归，不用于宣称全面 SOTA。

### B. 正式技术报告（公开发布）

- 通用语义：GenEval 2、T2I-CompBench++ 或 DPG-Bench 中至少两项互补基准。
- 人类偏好：固定 HPS v3 或 HPS v2.1/PickScore/ImageReward 之一，并保留一个未参与训练的偏好指标。
- 画质：一项 IQA + 分维度人工评审；有参考域时加 CMMD/FID。
- 文字、知识、多语言按模型宣称能力加入专项集。
- 至少一次同 prompt、同预算的盲测成对人工比较，给置信区间和标注协议。
- 发布逐样本分、judge 版本、prompt 模板和失败样本。

### C. 产品上线/采购决策

- 以真实用户任务分布建立私有集，公开 benchmark 仅用于防止过拟合内部集。
- 按业务场景分层：营销、电商、UI、人物、文字、编辑等分别设门槛，不用单一 overall 淘汰模型。
- 成对盲测评估“任务成功率、可用率、人工修图时间”，而非只问“哪张漂亮”。
- 记录延迟、吞吐、显存/成本、失败/拒答率、内容安全与版权流程。
- 固定模型版本并定期重测；API 模型升级后旧分不可直接沿用。

## 3. 预算有限时如何取舍

1. **优先买人工成对标注，而不是堆很多同源 CLIP 分数。** 200–500 条代表性 prompt、每条多模型同场比较，往往比十种高度相关自动分更有决策价值。
2. 语义使用能给出错误位置的方法：Soft-TIFA/DSG/GenEval 优于只有单一 cosine 的 CLIPScore。
3. 编辑任务先保证“两轴”：完成编辑与保持无关区域。其他指标后加。
4. 只测模型宣称的能力没有必要；应加入它最可能失败的反例，如否定、数量、多主体属性交换、稀有文字和重复编辑。
5. 不使用参考集时，不强算 FID。可报告 Vendi/组内多样性，但必须与语义成功率联合分析。

## 4. 不建议合成总榜；若业务必须合成

先为每个维度设硬门槛，再在合格模型内做透明的业务加权：

- 原始分先做方向统一，但不要把无界奖励分强行解释成概率。
- 使用预先声明的、与模型无关的归一化锚点；保存原始值。
- 任务宏平均，防止简单大类淹没难类。
- 公开权重、缺失值规则、并列和置信区间。
- 同时给出去掉任一指标后的敏感性分析；若排名剧烈变化，不宣称稳定领先。
