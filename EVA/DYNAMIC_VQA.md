# 动态 VQA 是什么？当前实现与计算方式

## 1. 一句话定义

本项目中的**动态 VQA**，是一种**按当前 Prompt 动态生成看图问答检查项，再由 VLM 逐项评分**的自定义任务对齐方法。

它用于回答：

> 这张生成图是否满足了用户这条 Prompt 中的对象、属性、数量、位置、文字、风格等要求？

它不是官方 VQAScore，也不是综合质量总分。

---

## 2. 整体流程

```text
原始用户 Prompt + 输入参考图（可选）
                │
                ▼
① 多标签路由器读取任务意图
                │
                ▼
② 动态生成任务检查项与保持检查项
                │
                ▼
③ VLM 看图逐项回答，输出 0–1 分和理由
                │
                ▼
④ 程序按问题重新对齐检查项并计算均值
                │
                ▼
动态 VQA（任务检查项均值）
保持检查项均值、全项通过率、最低检查项分别报告
```

Seedream 生成图片和动态检查清单的生成可以并行进行；图片返回后再让 VLM 逐项评审。

---

## 3. 两类检查项

### A. 任务检查项 `task_checklist`

检查用户要求完成的内容，例如：

- 是否有三名角色？
- 银发少女是否穿蓝绿色斗篷？
- 是否恰好有七只纸鹤？
- 招牌是否写“MOON”？
- 是否为工笔重彩＋蓝图线稿风格？

这些分数用于计算**动态 VQA**。

### B. 保持检查项 `preservation_checklist`

检查源图或参考图中应该保留的内容，例如：

- 人物身份是否保持？
- 未编辑背景是否保持？
- 招牌原文是否保持？
- 镜中人物和左右关系是否保持？

这些分数单独计算**保持检查项均值**，不放进动态 VQA。

如果某类检查项不存在，对应结果显示为 `null`，而不是 0。

---

## 4. 动态 VQA 怎么计算？

假设原始 Prompt 是：

> 一名银发少女穿蓝绿色斗篷，旁边有三只白猫，招牌写 MOON。

路由器生成四个任务检查项：

| 检查项 | VLM 分数 |
|---|---:|
| 是否有银发少女？ | 1.0 |
| 少女是否穿蓝绿色斗篷？ | 0.5 |
| 是否恰好有三只白猫？ | 0.0 |
| 招牌是否写 MOON？ | 1.0 |

则：

```text
动态 VQA = (1.0 + 0.5 + 0.0 + 1.0) / 4 = 0.625
```

`0.625` 只表示这组任务检查项的平均完成情况，不包含 PQ、OCR、CP/PF、保持度或其他指标。

---

## 5. VLM 输出的不是概率

当前实现让 VLM 返回结构化 JSON，例如：

```json
{
  "id": "cat_count",
  "question": "是否恰好有三只白猫？",
  "score": 0.0,
  "reason": "图中可见五只白猫，数量不符"
}
```

这里的 `score` 是 VLM 按评分规则给出的**评价分**，不是模型输出的 `P("Yes")` 概率。

这与以下官方方法不同：

| 方法 | 主要区别 |
|---|---|
| VQAScore | 通常用生成式 VQA 模型回答 Yes 的概率作为连续分 |
| TIFA | 预生成 QA，由 VQA 答案与标准答案匹配计算正确率 |
| DSG | 在 QA 上增加语义依赖图，处理父子问题依赖关系 |
| Soft-TIFA | 使用正确答案概率，并分别计算算术均值和几何均值 |
| 本项目动态 VQA | 针对每个新 Prompt 动态拆题，VLM 输出 0–1 分和理由，再由程序聚合 |

因此它可以称为**自定义动态 VQA 任务对齐分**，不能直接与其他论文中的 VQAScore 数值比较。

---

## 6. 程序如何防止 VLM 自己算错平均分？

VLM 可能重排检查项、改写问题，或自报一个不可靠的 `task_score`。当前程序会：

1. 要求返回每个检查项的 `id`、`question`、`score` 和 `reason`；
2. 优先按问题文本相似度重新匹配原始检查项；
3. 若无法可靠匹配，自动纠偏重试一次；
4. 由程序根据匹配后的检查项重新计算均值，而不是直接信任 VLM 自报均值。

核心逻辑相当于：

```python
task_score = sum(matched_check_scores) / len(matched_check_scores)
```

JSON 截断、漏答或错配也会触发一次重试。

## 7. 全项通过率和最低检查项是什么？

它们与动态 VQA 是不同统计量。

### 全项通过率

当前阈值为 `0.99`：

```text
全项通过率 = 得分 ≥ 0.99 的检查项数 / 全部检查项数
```

任务检查项与保持检查项都会计入这个比例，但它不纳入 PQ、OCR 或其他独立指标。

### 最低检查项

```text
最低检查项 = 所有检查项中的最低分
```

它用于暴露被平均值掩盖的关键失败。例如：

```text
任务检查项：[1, 1, 0.5, 0]
保持检查项：[1, 0.8]
```

则：

```text
动态 VQA = 0.625
保持检查项均值 = 0.9
全项通过率 = 2 / 6 = 33.3%
最低检查项 = 0
```

这些值不会再合成为总分。

## 8. 为什么低分时可能没有 failure_tags？

`failure_tags` 是 VLM 额外生成的文字标签，**不是由检查项分数自动计算出来的**。

因此可能出现：

```text
t8 = 0
t10 = 0
t11 = 0
failure_tags = []
```

这表示 VLM 给出了低分，却没有额外列出失败标签。它不代表没有失败，应直接查看 `checks` 中每个检查项的分数和理由。

当前版本保留这种行为，不自动把低分检查项转换成失败标签。

---

## 9. A/B/C/D/E Prompt 对比时为什么要固定检查清单？

如果：

- A 用原 Prompt 生成检查清单；
- B–E 分别用各自修改后的 Prompt 生成另一套检查清单；

那么动态 VQA 的题目和难度可能已经改变，各轮数值不再是同一把尺。

因此，公平的对比方式是：

```text
A 图 ─┐
B 图 ─┤
C 图 ─┼─ 都使用 A 原始 Prompt 的同一套检查清单重新评分
D 图 ─┤
E 图 ─┘
```

B–E 图仍然是用各自修改后的 Prompt 生成的，但**评审时统一使用 A 原始检查清单**。OCR 的目标文字也继续沿用原输入。

否则，指标变化可能同时包含：

1. 图片变化；
2. Prompt 变化；
3. 检查清单变化；
4. VLM 评审波动。

## 10. 动态 VQA 与其他指标的关系

```text
动态 VQA：任务检查项均值
保持检查项均值：保持条件的均值
PQ：感知质量，0–10
OCR Accuracy / NED / CER / F1：文字识别与字符串指标
文字布局分：文字载体、位置、重复和额外文字检查
CP / PF：参考主体保持 / 新 Prompt 遵循，0–4
全项通过率：检查项完全通过比例
最低检查项：最差检查项分数
```

例如 OCR Accuracy 为 1，并不表示文字位置正确；动态 VQA 高，也不表示保持度或 PQ 高。

这些指标分别使用，**不计算 Overall、Strict Overall、权重或跨指标归一化分**。

---

## 11. 温度与生图随机性

当前路由、VLM 评审和 Prompt Advisor 均显式使用 `temperature=0`，用于减少采样波动；`thinking={"type":"disabled"}` 只是关闭扩展思考，不等同于温度 0。

但温度 0 不能保证跨服务、跨版本完全一致，也不能消除生图的随机性：当前 Seedream 版本未固定 seed，所以 A/B/C/D/E 的图片差异仍可能来自随机生成，而不只是 Prompt 改写。

---

## 12. 优点与局限

### 优点

- 能针对每个新 Prompt 动态拆出具体条件；
- 可解释到每个检查项及其失败理由；
- 比单一图文相似度更容易发现漏对象、数量错误、属性错配和文字错误；
- 可同时覆盖文生图、编辑和参考图任务。

### 局限

- 检查清单由模型生成，可能遗漏条件或引入歧义；
- VLM 对左右手、遮挡、镜面、精确数量等可能误判；
- `0.5`、`0.8` 等部分分带有主观性，不是概率；
- 同一张图重复评分可能得到不同结果；
- 检查项均值会稀释少数关键失败，需要同时看全项通过率和最低检查项；
- 动态 VQA 不是官方 benchmark 分数，不能跨实现直接比较绝对值。

因此，实际使用时应把**原图、原始 Prompt、检查清单、逐项分数和理由**一起保留，而不是只看一个动态 VQA 数值。
