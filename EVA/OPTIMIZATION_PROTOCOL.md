# A–E 固定参数与最佳检查点优化协议

## 1. 为什么上一版仍会下降

上一版只解决了 Prompt 膨胀，仍有三处实验设计问题：

1. **长宽比未固定**：`size=2K` 只是分辨率档位，不是固定像素比例。
2. **没有最佳检查点**：每轮唯一图片无论好坏都进入下一轮。
3. **有效修改继承不足**：原始需求锚定避免了约束累积，但也可能丢掉上一轮已经有效的表达。

## 2. 本轮固定参数

| 案例 | 精确 size | 固定 seed 序列 |
|---|---|---|
| 微距琥珀腕表 | 2496×1664 | 41000, 41001, 41002, 41003 |
| 工笔蓝图荷塘 | 2816×1584 | 42000, 42001, 42002, 42003 |
| 中文温室看板 | 2816×1584 | 43000, 43001, 43002, 43003 |
| 木刻北极考察站 | 2496×1664 | 44000, 44001, 44002, 44003 |
| 雪景风格迁移 | 1776×2368 | 45000, 45001, 45002, 45003 |
| 腕表背景替换 | 2496×1664 | 46000, 46001, 46002, 46003 |

所有阶段固定：

seed 块规则：A 使用 `base_seed`；B 使用 `base_seed+0…3`；C 使用 `base_seed+4…7`；D 使用 `base_seed+8…11`；E 使用 `base_seed+12…15`。每个值都固定并写入对应 `generation.json`。

首次试跑起初让 B–E 共用一组 seed。发现“平台期时最佳 Prompt 不变，下一轮会重复同一批候选”后，停止了后续生成，保留已验收的 A/B，并改用上述分阶段 seed 块续跑 C–E。温室看板已提前写出的旧 C 阶段不纳入最终结果，按新 seed 块重跑并覆盖该阶段记录。

随后发现只生成改写 Prompt 会让一次不理想的改写失去最佳 Prompt 的竞争优势，因此 C–E 再加入两个“最佳 Prompt 原样重采样”控制候选。此前仅含改写候选的 C 阶段不纳入最终结果；A/B 保留，B 与 C–E 的候选组成差异在报告中明确公开。

- 同一个 Seedream 模型和输入参考图；
- 精确像素尺寸和固定 seed 序列；
- `output_format=png`、`response_format=url`、`watermark=false`；
- A 原始动态 VQA 与保持检查清单、OCR 目标文字；
- 同一个 VLM、`temperature=0`、`thinking=disabled` 和最大输出 token 数。

`guidance_scale` 虽存在于通用 Ark SDK 签名中，但当前 Seedream 端点实测返回 `InvalidParameter: not supported by the current model`，所以所有正式请求均不传该参数，并在 `generation.json` 中记录为 `null`。没有假装设置了它。

## 3. 最佳检查点如何继承

每轮输入给独立 Prompt 改写器的是：

```text
不可变的 A 原始需求
+ 历史最佳 Prompt
+ 历史最佳图片
+ 原始输入图（如有）
```

改写器必须尽量原样保留最佳图片中已满足原始要求的有效句子，只修改最多两个仍有歧义的已有要求。无法改善时返回最佳草稿，不再重置掉有效修改。

评分、逐项理由、OCR 结果和评估审计意见仍不进入 Prompt 改写阶段；它们只在外层候选验收中使用。

## 4. 候选与帕累托验收

- A：固定 seed 的单样本起点。
- B：保留首轮 4 个改写 Prompt 候选及其验收记录。
- C–E：每轮 4 个固定 seed 候选中，2 个原样继承最佳 Prompt，2 个使用新改写 Prompt；C、D、E 分别使用后续互不重复的固定 seed 块，避免平台期后重复同一批图片。
- 每个候选都使用 A 原始检查清单独立评分。
- 只有**没有受保护指标下降，且至少一个指标改善**时才允许替换最佳检查点。
- 多个合格候选之间只用字典序选择，不相加、不归一化、不计算总分。
- 没有合格候选则保留历史最佳图片和 Prompt，记为平台期。

受保护指标：

- 动态 VQA；
- 保持检查项均值；
- PQ、文字布局；
- 全项通过率、最低检查项；
- OCR Accuracy、NED、CER、Precision、Recall、F1；
- 编辑 SC/PQ（存在时）；
- 参考 CP/PF（存在时）。

CER 越低越好，其余数值越高越好。任务中不存在的指标不参与比较。检查清单中相同 ID 的逐项分数另做逐阶段下降审计，并在 HTML 中单列“逐项检查下降数”；不能用均值提升掩盖单项条件退化。

## 5. 结果应该怎样解读

本实验检验的是：

```text
最佳检查点继承 + Prompt 改写 + 固定参数生成 + 多候选帕累托选优
```

它不是单独测量 Prompt 的因果收益。A 是单样本，B–E 有 4 个候选，存在明确且公开的选优机制。

此外，A 的动态 VQA 如果已经为 1.0，就没有上升空间；接近 1.0 时最大增益也很小。报告必须同时给出 A→E 差值、每轮是否接受候选、所有落选原因和独立指标，不能只展示一条上升曲线。

## 6. 评审与改写仍可能被优化器利用

多候选选优会放大 VLM 误判的影响：如果某个错误图片被评审误给高分，它可能击败真正更好的候选。腕表 B 的人工抽查就存在疑点：检查项 `t10` 将“独立螺丝恰好三颗”判为满分，但图像顶部仍有一个疑似带槽螺丝，需要更严格的计数复核。该案例的 Prompt 还把“表背刻字”改写成“表壳可见刻字”，虽然原始检查清单未变，但说明改写语义保持和 VLM 位置判断都不能仅靠分数假设正确。

因此，本实验的递增首先表示**当前机评口径下的最佳检查点递增**。关键任务上线前仍应增加独立评审、可定位证据或人工抽查，不能把选优后的高分当作无误判证明。

结论必须分开说：

- 已实现：固定实际尺寸、固定并记录 seed、最佳检查点继承、所有受保护指标单调不降、相同检查 ID 逐阶段掉分数为 0。
- 总体改善：腕表、工笔荷塘、温室看板和背景编辑的 E 高于 A。
- 未实现：并非每个案例都在每一轮显著递增。腕表和工笔在 B 后平台期；温室在 B 达到满分；背景编辑在 C 后平台期；木刻从 A 起满分；雪景 16 个后续候选均未超过 A。
- 背景编辑 C 的胜者来自“继承最佳 Prompt”而非新改写，证明控制候选有必要。
- 正式 102 次生成全部完成。背景编辑 D 的 seed 46009 首次遇到 `ConnectError`，第二次成功，但仍未超过最佳检查点。

因此，这轮达成的是**单调不降、部分案例显著提升**，不是“所有案例 A<B<C<D<E”。雪景的高起点与木刻的满分天花板不能用不诚实的方式处理成持续增益。完整图片、候选、落选原因和逐项检查审计见 `EVA/optimization.html`。
