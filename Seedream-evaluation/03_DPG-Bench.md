# 长 Prompt 理解：DPG-Bench

## 1. 这个维度测什么？

高能力模型在“一个杯子在桌上”这类短 prompt 上可能都表现很好，但真实用户往往一次给出很多要求：

- 多个实体；
- 每个实体自己的属性；
- 多组空间/动作关系；
- 全局天气、时间和风格；
- 文字、数量和局部细节。

**DPG-Bench** 用 1,065 条长而稠密的 prompt，检查这些要求是否被完整实现，尤其适合发现“整体画面很像，但细节漏了一半”。

## 2. 五类语义检查

| 类别 | 检查内容 | 示例问题 |
|---|---|---|
| Global | 整体场景、时间、天气、风格 | 是否是在雨后的夜晚？ |
| Entity | 要求的对象是否存在 | 是否有三位骑自行车的人？ |
| Attribute | 对象属性是否正确 | 最左侧的人是否穿黄色雨衣？ |
| Relation | 空间、动作、交互关系 | 红色雨伞是否在长椅右边？ |
| Other | 其他可验证条件 | 指定招牌文字是否存在？ |

原始评分采用预构建的 Dense Prompt Graph、依赖关系和 mPLUG-large VQA。官方脚本默认每 prompt 4 张图。

## 3. 完整例子

假设 prompt 是：

> 雨后的城市街角，画面左侧有一家亮着暖黄色灯光的咖啡店，店门口摆两盆绿色植物；一位穿红色雨衣的女孩推着蓝色自行车，站在咖啡店右侧。她旁边有一只白色小狗。路面的积水倒映出咖啡店招牌，天空正在下雨，整体为写实摄影风格。

可以拆成以下检查：

| 类别 | 问题示例 | 假设回答 |
|---|---|---|
| Global | 是雨后且仍在下雨的街角吗？ | 正确 |
| Global | 是写实摄影风格吗？ | 正确 |
| Entity | 是否有咖啡店、女孩、自行车、小狗？ | 小狗漏掉，部分正确 |
| Attribute | 女孩是否穿红色雨衣？ | 正确 |
| Attribute | 自行车是否为蓝色？ | 错误，生成了黑色 |
| Attribute | 门口是否有两盆绿色植物？ | 正确 |
| Relation | 女孩是否在咖啡店右侧？ | 错误，生成在左侧 |
| Relation | 积水是否倒映招牌？ | 正确 |

可以看到，这张图可能第一眼很漂亮，也有咖啡店、女孩、自行车等大部分元素，但至少存在：

- 漏小狗；
- 自行车颜色错误；
- 人物与店铺位置关系错误。

这正是长 prompt 评测应暴露的问题。

## 4. 简化数值示例

为了理解分项报告，假设另一组样本在五类上的正确比例为：

| 类别 | 正确/总问题 | 类别分 |
|---|---:|---:|
| Global | 2/2 | 1.000 |
| Entity | 4/5 | 0.800 |
| Attribute | 5/8 | 0.625 |
| Relation | 1/3 | 0.333 |
| Other | 1/1 | 1.000 |

如果**仅为演示**采用五类等权平均：

`(1.000+0.800+0.625+0.333+1.000)/5 = 0.752`

总体约 75.2%，但 Relation 只有 33.3%。这说明只报 overall 会掩盖关键短板。

> 实际论文结果必须使用 DPG 官方脚本及依赖规则，不能用这段简化公式替代官方实现。

## 5. 与 VQAScore、Soft-TIFA 的关系

- **VQAScore**：整段 prompt 问一次，便宜、适合大规模初筛。
- **Soft-TIFA**：原子概率 + AM/GM，适合原子能力和联合满足。
- **DPG-Bench**：专门的长稠密 prompt、依赖图和五类诊断，适合发现漏项。

三者结合时，DPG 的分项可以帮助解释为什么整段 VQAScore 很高，但实际仍有漏对象。

## 6. 推荐报告

- Overall；
- Global / Entity / Attribute / Relation / Other；
- 按 prompt 长度或实体数分层；
- 每 prompt 4 seed 的平均成功率；
- 每类失败的典型案例；
- 是否启用 prompt 改写，以及改写后丢失了多少约束。

## 7. 常见误用

- 用模型自动缩短 prompt 后，只评缩短版，不检查原始要求是否被丢弃。
- 只报总体分，不报 Relation。
- 将 mPLUG 的误判直接视为生成错误，不做低分抽检。
- 用 best-of-4 替代 4 图均值，却不注明。
