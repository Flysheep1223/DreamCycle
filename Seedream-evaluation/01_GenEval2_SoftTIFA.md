# 组合指令遵循：GenEval 2 / Soft-TIFA

## 1. 这个维度测什么？

它检查 prompt 中的**对象、属性、数量、位置关系等原子条件**是否真正出现在图中。相比“这张图整体像不像这句话”，它更适合回答：

- 两个对象是否都存在？
- 颜色有没有绑错对象？
- 数量是不是准确？
- 左右、前后等关系是否正确？
- 条件一多，模型是否开始漏项？

对能力较强的模型，简单单对象题往往接近饱和，Soft-TIFA 的原子分解和 GenEval 2 的多原子 prompt 更有区分度。

## 2. 数据与基本流程

使用 **GenEval 2 的 800 条 prompt**。每条 prompt 带：

- `atom_count`：原子条件数；
- `vqa_list`：每个原子对应的问题和正确答案；
- `skills`：object、attribute、position、count 等技能标签。

评分时，VQA 模型不只知道最终 Yes/No，而是保留它分配给**正确答案的概率** `p_i`。

## 3. AM 与 GM 分别是什么？

### Soft-TIFA AM：平均每个条件会多少

`AM = (p_1 + ... + p_n) / n`

越高越好。适合分析每个技能，例如 counting 平均能力。

### Soft-TIFA GM：整条 prompt 是否联合满足

`GM = (p_1 × ... × p_n)^(1/n)`

越高越好。某个必要条件概率很低时，GM 会明显下降，适合衡量“所有要求一起成立”。

**AM 和 GM 不是越高越相同，也不应再平均成一个新分。**

## 4. 数值例子：为什么两个都要报？

假设 prompt 是：

> 一只红色的猫坐在蓝色椅子上，旁边有两本书。

简化成 5 个原子问题：

| 条件 | 正确答案概率 |
|---|---:|
| 图中有猫 | 1.00 |
| 猫是红色 | 1.00 |
| 图中有椅子 | 1.00 |
| 椅子是蓝色 | 1.00 |
| 旁边有两本书 | 0.20 |

则：

- `AM = (1+1+1+1+0.2)/5 = 0.84`
- `GM = 0.2^(1/5) ≈ 0.725`

另一个模型在 5 个条件上都得到 `0.8`：

- `AM = 0.8`
- `GM = 0.8`

结果是：

| 模型 | AM | GM | 直观理解 |
|---|---:|---:|---|
| A | **0.84** | 0.725 | 四项几乎确定，一项很可能错 |
| B | 0.80 | **0.80** | 每项都有一定不确定，但没有明显短板 |

如果产品要求“整条 prompt 尽量全对”，B 的 GM 更有意义；如果分析平均原子能力，A 的 AM 更高。

> 上述概率是为了讲公式而虚构的。真实分数由固定 VQA judge 输出。

## 5. 一个典型反例

Prompt：

> 红色方块在蓝色球左边，黄色方块在蓝色球右边。

生成图里所有对象和颜色都出现了，但左右关系反了。

- CLIPScore 可能仍然很高，因为“红方块、黄方块、蓝球、左右”这些概念都在。
- Soft-TIFA 中对象和颜色原子可能高分，但 position 原子低分。
- AM 只温和下降，GM 会更明显地反映整条 prompt 没完全满足。

## 6. 怎么报结果最有用？

建议至少给：

| 指标 | 含义 |
|---|---|
| Soft-TIFA GM Overall | 整条 prompt 联合满足能力 |
| Soft-TIFA AM Overall | 平均原子能力 |
| Object AM | 对象存在能力 |
| Attribute AM | 属性与绑定能力 |
| Count AM | 数量能力 |
| Position AM | 空间关系能力 |
| 按 atom_count 分层 GM | 条件增多时的性能衰减 |

## 7. 常见误用

- 把 AM 当整图完全正确率；AM 高可能仍有一个关键条件失败。
- 把 GM 当平均原子能力；GM 对低概率项更敏感。
- 换 VQA judge 后直接比较原始分。
- 将 VQA 的误判全部归为生成模型错误，应抽查低分图。
- 只报 overall，不看数量和位置等薄弱技能。
